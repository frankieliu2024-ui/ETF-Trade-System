# ETF与市场监测数据接口使用规范 V1.0

> 生效日期：2026-08-23  
> 适用系统：ETF波段交易系统 V2.2.15  
> 数据服务：同花顺金融数据服务（`hithink-finance` CLI；REST仅作短窗口验收备援）  
> 定位：本规范是四文件体系的辅助数据规范，不是第五个规则来源，不生成风险许可、机会等级、金额、生命周期或买卖动作。

## 0. 审计结论

`hithink-finance`覆盖元信息、A股行情与公司行为、财务、估值、交易日历、集合竞价、指数与板块、公募基金、特色数据和全市场导出。本ETF项目日常直接使用标的检索、ETF场内快照、ETF历史日线、A股指数快照和必要的A股指数历史；基金资料、持仓披露、净值、收益及其他板块数据只在形成独立研究需求时启用，不进入默认采集链。

契约层面明确支持ETF历史日线，字段含开盘、最高、最低、收盘、成交量和成交额；快照另含昨收、涨跌额、涨跌幅、振幅和换手率。历史端点当前仅支持日线，不支持分钟K、tick或Level-2，也不提供复权参数；单次查询区间最多5年。

2026-08-23已使用当前账号完成线上验收：原八只ETF均通过元信息、快照和近期历史日线请求；进一步通过CLI完成17只ETF工具的长历史补齐，共19,672行，全部更新至2026-08-21且无缺失、重复日期或OHLC关系异常。原八只与正式Excel的交易日期、成交量一致，仅在2024-09-30发现两处最小价格跳动差异，已保留双来源而未覆盖。验收报告位于`专项回测/outputs/hithink_acceptance_20260823/`，长历史复核位于`专项回测/outputs/hithink_etf_audit_20260823/`。

接口可替代正式八ETF及同花顺覆盖的A股核心指数行情抄录、成交量/成交额采集、历史日线补齐和条件扫描输入；不能替代券商账户、持仓、成本、盈亏、现金、真实成交、委托状态截图，也不能替代IOPV/折溢价、盘口、分钟路径或本服务范围外的海外指数和商品数据。它不具备自动交易职责。

## 1. 可用接口与项目用途

### 1.1 全量能力概览

|领域|端点数|本项目用途|
|-|-:|-|
|元信息|2|代码消歧、ETF资产类别确认；日常必需|
|A股行情与公司行为|3|个股或A股辅助观察；不用于ETF主行情|
|财务、估值、日历、集合竞价|8|按专项研究启用；非ETF日常主链|
|指数与板块|4|A股指数/板块辅助验证；不等同于海外指数覆盖|
|公募基金|28|ETF快照、ETF日线及基金资料；日常主链所在|
|特色数据|11|个股市场环境研究；不直接触发ETF交易|
|全市场导出|3|A股本地库建设；不用于八ETF逐日主采集|

### 1.2 日常主接口

|接口|输入|输出要点|使用规则|
|-|-|-|-|
|`GET /api/meta/tickers/search`|名称、代码或完整`thscode`|`thscode`、名称、交易所、`asset_type`|首次接入、代码变更疑问或接口返回3001时使用；必须确认`asset_type=fund-etf`|
|`GET /api/fund/market/snapshot`|单个ETF `thscode`|最新价、开高低、昨收、涨跌额/幅、振幅、成交量、成交额、换手率|一次只查一只；用于有明确采集时点的快照，不冒充分钟K或券商账户事实|
|`hithink-finance fund history`|单个ETF `thscode`、`interval=1d`、起止日期|日期、OHLC、成交量、成交额|长历史主入口；按CLI支持窗口拆分、去重并原子替换通过质量检查的数据|
|`GET /api/fund/market/historical`|单个ETF `thscode`、`interval=1d`、起止毫秒时间戳|日期、OHLC、成交量、成交额|只用于近期验收或备援；当前长区间请求可能回退为仅2026年154行，禁止直接覆盖完整历史|
|`hithink-finance index snapshot`|一个或多个A股指数`thscode`|最新价、开高低、昨收、涨跌幅、成交量、成交额|上证指数和创业板指进入默认读取；不能据此声称覆盖海外指数|
|`hithink-finance index history`|单个A股指数及起止时间|指数日线OHLC等可用字段|专项或缺口补齐时调用；逐指数验收，不用相似指数静默替代|

REST基础地址为`https://fuyao.aicubes.cn`，通过请求头`X-api-key`认证。只有HTTP 200且业务信封`code=0`才算成功；`data=null`的业务错误不得当成空行情。API Key只从`HITHINK_FINANCE_API_KEY`或用户级受限凭据读取，不得写入项目、脚本参数、日志、文档或Git。

## 3. 字段与口径

### 3.1 规范字段

|标准字段|接口字段|用途与口径|
|-|-|-|
|交易日|`date_ms`|转为Asia/Shanghai自然日；保存原始毫秒值|
|开盘/最高/最低/收盘|`open_price`/`high_price`/`low_price`/`close_price`|保存接口连续价格；响应中`adjust`为空，未取得正式复权声明前不得命名为前复权、后复权或不复权|
|成交量|`volume`|保留接口原值；单位未通过线上样本核定前不擅自标为“股”或“手”|
|成交额|`turnover`|保留接口原值；与现有Excel/截图核对数量级后确定展示单位，不在底层预先除以万或亿|
|快照涨跌幅|`price_change_ratio_pct`|百分数原值，仅用于对应快照时点|
|快照换手率|`turnover_ratio_pct`|百分数原值；历史日线端点不提供|
|来源时间|响应`timestamp`及采集时间|分别保存服务数据时间与本地采集时间，不用采集时间冒充市场时点|

历史涨跌幅、振幅、CLV、均线、成交额倍率、连续涨跌和相对强弱均由标准化日线派生，不把派生值伪装成接口原始字段。无振幅时CLV保持不可计算，不补零。跨ETF比较成交量前必须说明单位和份额差异；优先比较各自成交额相对历史均值，而不是绝对成交量。

### 3.2 收盘与时点

日常收盘扫描只使用完整收盘日线。盘中快照必须记录实际采集时间并标注“盘中”，不得回填为15:00收盘。接口数据、行情列表和券商持仓估值出现差异时三者分别保留来源，不相互覆盖；账户盈亏继续以券商账户事实为准。

## 4. 截图替代边界

|现有人工事项|替代程度|规范|
|-|-|-|
|八ETF日线OHLC、成交量、成交额|可替代|历史接口作为首选机器源；上线初期保留抽样截图复核|
|八ETF收盘价、涨跌幅、振幅、换手率|大部分可替代|15:00后采快照并与历史收盘交叉核对；换手率仅来自快照|
|上证指数、创业板指快照|可替代|与八ETF同时读取最新价、OHLC、涨跌幅、成交量和成交额；接口响应时间不冒充市场最终收盘时点|
|历史Excel补齐、T+1/T+3/T+5等窗口|可替代采集|由日线自动生成研究数据；规则解释仍由现有体系负责|
|11:30等固定盘中观察|部分替代|定时快照只能证明采集时点状态，不能还原盘中路径|
|券商持仓、成本、盈亏、现金、成交、委托|不可替代|继续以券商截图和成交记录为唯一事实源|
|IOPV、折溢价、盘口、分钟K、tick、Level-2|不可替代|当前契约不提供，不用日线或快照近似冒充|
|NDX、SOXQ、KS11、TWII、N225、HSTECH等海外监测|不可替代|本服务契约不覆盖海外市场主数据，保留原数据源和时点说明|

上线后的截图策略采用“机器采集为主、异常留证”：ETF完整收盘日线已经通过正式Excel交叉验收，日常不再要求人工逐只截图；价格/成交额异常、接口缺失、数据源冲突或重大盘中决策节点可额外留图。券商账户与真实成交留证频率不因本接口降低。

## 5. 接入架构与四文件职责

```text
hithink-finance CLI
  → 原始响应层（不可改写，含request_id、采集时间、查询参数，不含API Key）
  → 校验层（认证、code、标的、日期、OHLC关系、重复、缺口、单位）
  → 标准行情层（八ETF＋A股核心指数统一字段与派生指标）
  → 行情档案/专项数据入口
  → Dashboard状态判断与经验库复盘
  → MASTER规则执行
```

接口适配器不得直接写MASTER，不得从行情自动生成风险许可、机会等级、Trial/Confirm、固定金额或卖出份额。推荐数据目录是`data/market/raw/hithink/YYYY-MM-DD/`、`data/market/normalized/etf_daily/`和`data/market/audit/`；目录只承载数据和质量报告，不承载交易结论。

四文件职责保持不变：

- MASTER只定义允许什么及数据使用边界；只引用本规范，不保存端点、Key、原始响应或采集状态。
- Dashboard只保存当前账户、生命周期和下一节点；可引用已经通过校验的行情结果，但必须注明数据时点和来源，不保存采集实现。
- 行情档案是接口数据的正式归属，登记数据源、字段口径、日期覆盖、异常和抽样核对结果；不保存交易判断。
- 经验库只在复盘中引用关键数据证据和数据质量影响；不复制完整日线，不把接口信号变成规则。

本规范负责“如何采集和验收”，不改变`MASTER > Dashboard > 当前行情与成交 > 经验库 > 行情档案 > 历史聊天`的内容优先级。出现规则冲突时以MASTER为准；出现账户事实冲突时以券商账户/成交证据为准；出现市场数据冲突时保留各来源并在行情档案登记核对结果。

## 6. 上线验收与运行

### 6.1 一次性上线验收

1. 在用户级安全位置配置统一API Key，不写入项目；发起最小元信息请求确认认证。
2. 对八只ETF逐一执行元信息检索，核对代码、名称、交易所及`asset_type=fund-etf`。
3. 对八只ETF逐一请求快照与最近5个交易日日线；要求HTTP 200、`code=0`、标的一致且至少返回预期交易日。
4. 将最近5日OHLC和成交额与当前已核对Excel逐行比较；价格必须一致或差异有明确来源，成交量/成交额必须完成单位换算核定。
5. 校验`low≤open/close≤high`、日期唯一递增、非交易日无伪记录、成交量和成交额不被空值补零。
6. 保存不含密钥的验收报告。只有八只全部通过，才把状态从“契约支持”改为“已实测接通”；个别失败不得用相似ETF替代。

### 6.2 日常运行

盘中决策节点采集正式研究池八ETF、上证指数和创业板指十项快照；交易日15:00后再采集正式研究池ETF完整日线。如日线尚未准备，只进行有限重查并保留失败记录，不用快照静默冒充最终日线。每次按`thscode+date`幂等合并，只有通过末日、重复、缺失和OHLC检查的数据才可原子替换标准文件。大批历史结果落盘，不写入对话或核心文档全文。

正式长历史实现位于`专项回测/refresh_etf_history_hithink_cli.py`，盘中十项快照实现位于`专项回测/refresh_v2215_market_snapshot_hithink_cli.py`；后者一次读取八ETF、上证指数和创业板指，并保存原始响应、标准CSV及质量清单。`专项回测/hithink_etf_data.py`与`专项回测/accept_hithink_etf.py`保留用于REST近期验收。`fetch_v2214_pool_data.py --hithink-primary`不得再作为长历史正式刷新入口，以免REST回退短区间覆盖完整CSV。海外和商品监测继续使用各自已核验来源。

```powershell
python accept_hithink_etf.py
python refresh_etf_history_hithink_cli.py
python refresh_v2215_market_snapshot_hithink_cli.py --label 0930
```

每次运行输出：数据源、接口版本/契约版本、ETF及指数成功数、时间范围、总行数、缺失与重复、单位口径、重试次数、最后错误和质量结论。任何质量失败只阻断受影响数据进入行情档案，不阻断四文件体系的人工备援流程。

## 7. 与V2.2.15的关系

本接口的项目价值是降低ETF与A股核心指数行情采集成本、提高机会和市场环境扫描效率并扩大历史验证能力，符合V2.2.15“在可接受风险内提高可实现收益和资本效率”的方向。它只提高信息取得效率和证据完整度，不提高交易权限，不改变风险观察区Confirm关闭、固定金额档位、生命周期或卖出规则。V2.2.15研究池替换来自专项回测结论，不是接口自动触发；更高扫描频率也不得被误用为更高交易频率目标。

## 8. 版本与变更控制

V1.0依据2026-08-23随技能安装的官方离线REST契约形成。后续端点、字段、限额或资产覆盖发生变化时，先更新并重跑线上验收，再升级本规范；未验收的新字段不得直接进入正式研究。接口契约只能证明服务设计范围，当前账号权限与线上数据完整性始终以实际授权请求为准。
