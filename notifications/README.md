# 通知事件层

通知层只推送具有独立行动或关注价值的事项，不生成盘中交易动作。PushPlus 是高价值信息与用户行动通道，不是 GitHub 运行日志出口。通知记录统一由 `data/state/notification_center.json` 管理。

## 一、市场分类

市场类通知统一只使用三类用户可见市场名称：

- **A股市场**：上证指数（000001）、科创50指数（000688）、创业板指（399006）、全部持仓ETF与观察ETF，以及当日账户确认的底仓个股。
- **美股市场**：正式指数层继续区分纳斯达克100指数（NDX）、费城半导体指数（SOX）；扩展时段和现金盘路径使用纳指100ETF代理（QQQ）、半导体ETF代理（SOXX）等现有代理，不得混淆。
- **亚太市场**：日经225指数（N225）、韩国综合指数（KOSPI）、台湾加权指数（TWII）、恒生科技指数（HSTECH）。香港不再单独形成第四类用户可见市场。

底层仍复用现有 A股、overseas、US 三条行情采集链，不新增provider、平行交易规则系统或通知队列。

## 二、通知价值原则

不设置夜间免打扰，也不以“A股是否正在交易”作为唯一门禁。通知只回答四个问题：发生了什么、为什么值得现在知道、对ETF系统意味着什么、用户现在需要做什么。

普通行情波动、研究更新、维护成功、自动修复成功、例行状态刷新及无独立价值的变化只后台记录。市场类PushPlus分为三种：

1. **开盘有价值信号**：不固定逢开必报。只有开盘后出现明显方向、显著横截面分化或其他足以占用注意力的结构变化才推送。
2. **盘中异动**：极端涨跌、突然涨跌达到通知注意力阈值时即时推送。
3. **固定收盘总结**：A股市场、美股市场、亚太市场各保留一次收盘总结，必须包含最终方向、日内路径、结构演化及对下一A股节点的启示。

通知阈值只控制注意力，不属于 `ETF规则_MASTER.md` 的交易规则，不新增风险许可、生命周期或金额档。

## 三、A股市场

### 开盘

A股开盘不再固定推送。09:35后的连续竞价节点只有在以下任一注意力条件出现时形成“开盘有价值信号”：核心指数绝对涨跌约达到1%、监测ETF绝对涨跌约达到2%、或ETF横截面领先与落后差约达到2.5个百分点。上述阈值只是通知门槛。

集合竞价与连续竞价分开解释。开盘通知只能要求刷新正式判断，不能直接产生买卖动作。

### 收盘

15:00正式close形成后固定发送一次A股市场收盘总结。价格有效时点固定为15:00；如果provider在15:10/15:20补查，必须单列为观测时间，不能冒充收盘行情时点。

摘要覆盖上证指数（000001）、科创50指数（000688）、创业板指（399006）、ETF横截面领先/靠后对象，以及现有 `intraday_path_features.json` 的路径变化、低点修复、距高点回撤和近期斜率。

A股收盘PushPlus只负责即时行情结构摘要；15:30的“ETF交易复盘”继续负责账户、风险许可、生命周期、资本效率、持仓/卖出判断和CASE完整闭环。

## 四、美股市场

复用现有 `US extended-hours pulse`，按 `America/New_York` 自动处理夏令时和冬令时。

### 开盘

美股开盘不再固定推送。美东09:35后的稳定窗口只有在纳指100ETF代理（QQQ）或半导体ETF代理（SOXX）绝对涨跌约达到1%，或二者开盘分化约达到1个百分点时才形成“开盘有价值信号”。

### 收盘

美东16:05后的首个有效POST_MARKET脉冲固定形成一次现金盘收盘总结。总结必须读取现金盘开盘、收/现价、高低点、相对前收、相对开盘、自低点修复、距高点回撤、区间位置，以及首小时/中段/尾段5分钟bar路径变化，不能只写最终涨跌幅。

盘前/盘后异动使用扩展时段相对最近现金盘收盘的变化，不得把上一现金盘旧涨跌重新包装成当前异动。

美股总结只形成海外结构证据，继续经过“外部结构 → 本地传导 → ETF自身反馈 → 机会判断”，不得直接形成A股ETF买卖动作。

## 五、亚太市场

亚太市场统一覆盖日本、韩国、台湾、香港，但不假定它们同步开盘或同步收盘。

### 开盘

亚太开盘没有固定时间，也不等待所有市场开盘。日本、韩国、台湾、香港任何一个当天已经开盘且取得有效provider行情，只要较前收绝对涨跌约达到1%，就可以立即以“亚太市场｜开盘有价值信号”推送。

例如韩国综合指数（KOSPI）在台湾、香港尚未开盘时出现明显上涨或下跌，系统可以先推送韩国触发的亚太信号，并明确当前“已开盘且有效市场数”。随后台湾或香港出现相反反馈时，应更新区域结构判断，而不是机械沿用第一条开盘方向。

### 收盘

亚太市场固定收盘总结统一放在香港16:00收盘之后，现有overseas workflow继续运行到北京时间16:30以容纳provider和GitHub Actions调度延迟。总结覆盖当日实际有效的日经225指数（N225）、韩国综合指数（KOSPI）、台湾加权指数（TWII）、恒生科技指数（HSTECH）；当地休市市场不得伪造当日行情。

亚太收盘总结必须保留各市场真实provider时点，并说明区域共振、分化以及与A股反馈是否背离。香港16:00晚于A股15:00，因此香港部分属于A股收盘后的补充证据，只进入下一A股交易节点，不反向改写A股15:00正式事实。

恒生科技指数（HSTECH）的结构或异动应直接复核恒生科技ETF（513180）的自身反馈。

## 六、极端涨跌与突然涨跌

`scripts/send_market_shock_notification.py` 统一处理A股市场、美股市场和亚太市场异动。

当前通知层阈值：

- A股正式指数当日绝对涨跌约≥2.5%；监测ETF约≥4.0%：极端涨跌候选；
- 美股核心代理、亚太正式指数当前有效阶段绝对涨跌约≥2.0%：极端涨跌候选；
- 相邻有效脉冲20分钟内绝对变化约≥1.0%：突然涨跌候选。

防刷屏规则：同一对象、同一方向的“突然涨跌”采用45分钟冷却；“极端涨跌”同一市场日、同一对象、同一方向最多主动通知一次；如果先突然涨跌后升级为极端涨跌，允许追加一次。已经结束交易时段的旧涨跌不得因workflow重跑重新包装成新异动。

A股异动必须发生在当日有效交易/收盘窗口；亚太异动必须来自北京时间当日有效市场日期；美股PRE_MARKET/POST_MARKET必须使用扩展时段相对最近现金盘收盘的变化。

## 七、统一模板

开盘有价值信号、固定收盘总结和异动通知均优先采用：

`发生了什么 → 日内/阶段路径 → 为什么值得现在知道 → 对ETF系统的启示 → 现在怎么做 → 数据时点 → 解释边界`

固定收盘总结必须有路径描述；开盘信号只在有价值时产生；异动通知必须说明触发对象、当日/阶段变化及最近脉冲变化。

正式交易机会、账户确认、成交确认和系统故障可以保留业务特有栏目，但不得退回只有“状态变化，请重新检查”的低信息量模板。

## 八、通知生命周期与执行边界

通知记录使用 `CREATED → SENT/WAITING_CONFIRMATION → CONFIRMED → ARCHIVED`，超过确认窗口进入 `EXPIRED`。同一 `source_event_id` 不重复推送；失败或未发送不视为用户确认。

用户明确确认的延迟成交仍通过既有正式账户事实/成交同步链处理，不从最终持仓反推成交。通知模块不得修改MASTER、扩大交易权限、创建金额或自动下单。

系统事件、A股市场总结/异动、收盘账户提醒和正式决策重评由现有 `.github/workflows/decision-notification.yml` 承载；美股市场总结/异动由 `.github/workflows/us-extended-hours-pulse.yml` 承载；亚太市场总结/异动由 `.github/workflows/overseas-preopen-pulse.yml` 承载。
