# 通知事件层

通知层只推送具有独立行动或关注价值的事项，不生成交易权限或自动下单。PushPlus 是高价值信息与用户行动通道，不是 GitHub 运行日志出口。通知状态统一保存在 `data/state/notification_center.json`。

## 一、最高原则：按价值通知，不按市场通知

主动通知不再以“A股 / 美股 / 亚太”作为资格分类。三类市场仍保留在底层行情采集、provider、交易时段、Point-in-Time 和跨市场传导解释中，但**任何当前正式监测对象，只要新事实足以改变注意力排序、风险传导理解、候选比较、持仓风险收益或下一节点准备，就可以形成通知。**

适用对象包括：

- 全部正式指数；
- 全部持仓ETF与观察ETF；
- 当日账户确认的打新底仓个股；
- 已经由具体ETF、行业冲击或传导假设条件调用的个股；
- 美股扩展时段正式使用的ETF代理及条件行业个股。

市场归属只回答“数据来自哪里、现在处于什么交易阶段、如何向A股传导”，不回答“有没有资格通知”。

通知价值固定问四件事：

1. 这个事实是不是新的，而不是旧行情重放；
2. 它是否足以改变当前注意力排序、传导理解、候选比较、持仓风险收益或下一节点准备；
3. 用户现在是否需要知道或行动；
4. 如果不通知，会不会降低下一步判断或执行质量。

如果以上答案均是否，则只后台记录。

## 二、用户可见标题体系

标题按“为什么收到这条消息”分类，而不是按市场分类。当前稳定使用以下主类；这是通知语言，不是MASTER生命周期或风险等级：

- `【异动提醒】`：市场对象出现有价值的新结构事件，包括开盘异常、快速重定价、极端波动、方向反转、显著分化，以及未来经CASE证明有同等价值的新事件；
- `【收盘总结】`：固定收盘节点形成的高信息密度总结；标题突出当天最重要的新事实，不机械写“某市场收盘”；
- `【观察机会】`：唯一主候选进入值得持续准备但尚未达到Trial/Confirm的状态，且该变化实质改变注意力排序；
- `【Trial机会】`：正式决策已形成Trial机会，正文必须给出金额、资金来源、失效条件和数据时点；
- `【Confirm机会】`：正式决策已形成Confirm机会，正文必须给出金额、资金来源、验证依据和失效条件；
- `【机会失效】`：此前观察/Trial/Confirm候选实质失效或主候选发生有意义切换；
- `【持仓动作】`：正式持仓判断要求明确合法份额降低风险或全部退出；
- `【风险许可】`：风险许可发生实质变化，尤其是新增权限关闭或重新开放；
- `【成交确认】` / `【账户确认】`：真实成交、持仓数量或资金事实需要用户确认；
- `【系统阻塞】`：真实生产故障已经影响或将直接阻塞下一个有效交易判断节点，且自动修复到达安全边界。

普通系统恢复、维护成功、研究更新、普通行情变化、普通创新高/新低、普通排名变化不单独主动通知。若它们实质改变正式判断，可通过上述相应类别体现。

标题示例只表达格式，不形成新规则：

- `【异动提醒】韩国综合指数（KOSPI）开盘快速上冲，区域风险偏好重定价`
- `【Trial机会】黄金ETF（518880）｜5,000元Trial机会`
- `【Confirm机会】通信ETF（515880）｜新增资本验证通过`
- `【机会失效】通信ETF（515880）｜原Trial假设失效`
- `【持仓动作】科创50ETF（588000）｜降低风险至明确合法份额`
- `【收盘总结】科创50指数（000688）录得异常强势日，科技方向全天占优`

## 三、市场有价值事件：当前五类

系统不把“突然涨跌、极端涨跌”当作全部事件。当前保留五个事件族；以后真实CASE若证明存在同等价值的新事件，可以扩展，但不得为了完整性堆标签。

### 1. 开盘异常

开盘本身不是事件；明显跳空、方向、横截面结构或开盘后快速确认才是事件。不同市场不要求同步开盘，谁先产生有价值的新事实，谁先通知。

当前注意力参考：A股核心指数约1%、监测ETF约2%或ETF横截面差约2.5个百分点；美股核心代理约1%或核心代理分化约1个百分点；日、韩、台、港正式指数约1%。这些数字只控制注意力，不属于MASTER规则。

### 2. 快速重定价

对应此前口语中的“突然涨跌”。强调**速度**：相邻有效行情脉冲在短时间发生足以改变当前结构理解的变化。指数/ETF当前参考约20分钟内1%；个股因天然波动更高，可使用更高的注意力阈值，避免把正常个股噪声推送为系统事件。

离散脉冲不得伪装成完整分钟路径。

### 3. 极端波动

强调**绝对幅度已经进入非常规区间**。当前参考：A股正式指数约±2.5%、监测ETF约±4%、账户/条件个股约±5%；美股核心代理和亚太正式指数约±2%，美股条件个股采用更高阈值。

极端幅度只触发重新评估，不直接产生买卖动作。

### 4. 方向反转

价格先形成足够大的单向日内幅度，随后大幅回吐或修复，使原来的“单向强/弱”解释可能失效。A股指数、ETF、账户底仓个股以及具备可靠当日日内OHLC的海外对象可使用这一事件；美股扩展时段与现金盘不得跨时段拼接伪造反转。

### 5. 显著分化

即使没有单个对象极端波动，相对差也可能改变传导判断。包括核心指数之间、ETF横截面、QQQ与SOXX、日韩台港之间，以及已经形成独立传导假设的标的与其基准之间的显著背离。

显著分化提醒系统不能继续用单一“市场强/弱”概括全部机会和风险。

普通放量、普通创新高/低、普通排名变化不单独成为通知事件；只有当它们实质改变相对强弱、风险收益、候选或已有假设时，才进入有价值事件或正式交易通知。

## 四、防刷屏与事件升级

去重应围绕“同一事实是否已经通知”，而不是围绕市场分类。

- 同一对象、同一方向的快速重定价采用45分钟冷却；
- 极端波动、方向反转、显著分化在同一市场日、同一对象/结构、同一方向默认只主动通知一次；
- 快速重定价随后升级为极端波动或方向反转，可以追加一次，因为信息含义已经变化；
- 同一行情演化同时满足多个类别时，优先合并为一条更高信息量通知，不机械多发；
- 已经结束交易时段的旧行情不得因workflow重跑重新包装成当前事件。

A股事件必须属于当日有效交易/正式close窗口；海外事件必须使用对应市场当前有效阶段和真实provider时点。美股PRE_MARKET/POST_MARKET必须使用扩展时段相对最近现金盘收盘的变化。

## 五、收盘总结

收盘总结与异动提醒不同：收盘是信息集完成的天然节点，因此保留固定总结，但标题必须突出当天最重要的新事实，而不是机械“某市场收盘”。

### A股

15:00正式close后固定形成一次总结，覆盖上证指数（000001）、科创50指数（000688）、创业板指（399006）、全部ETF横截面、关键账户底仓反馈和日内路径。价格有效时点固定解释为15:00；provider晚于15:00的补查时间必须单列。

A股收盘PushPlus负责即时结构总结；15:30“ETF交易复盘”继续负责账户、风险许可、生命周期、资本效率、持仓/卖出和CASE完整闭环。

### 美股

现金盘收盘固定总结必须包含开盘、高低点、相对前收、相对开盘、低点修复、距高点回撤、区间位置以及首小时/中段/尾段路径，不能只报最终涨跌幅。

所有美股证据继续经过：

`外部结构 → 本地传导 → ETF自身反馈 → 机会判断`

不得直接形成A股ETF买卖动作。

### 日、韩、台、港与A股尾盘

固定主要总结放在北京时间14:35—14:55，利用日经225指数（N225）、韩国综合指数（KOSPI）、台湾加权指数（TWII）已经形成的收盘结果，为A股最后约20分钟提供外部结构参考；仍在交易的恒生科技指数（HSTECH）明确标为盘中，并尽量加入当时A股反馈判断共振或背离。

香港16:00后不固定再发第二篇。只有恒生科技指数（HSTECH）后续变化足以实质改变14:35的区域判断，或者14:35主总结缺失，才追加更新。香港16:00信息只进入下一A股交易节点，不反向改写当天A股15:00正式事实。

## 六、统一正文模板

市场异动、收盘总结和正式交易机会虽然标题不同，但正文优先回答：

`发生了什么 → 路径/证据如何演化 → 为什么值得现在知道 → 对风险传导/候选/持仓意味着什么 → 现在怎么做 → 数据时点 → 解释边界`

Trial/Confirm通知必须进一步明确：风险许可、机会状态、固定金额档、资金来源、失效条件和最近复核节点。持仓动作必须明确合法份额。账户/成交确认必须明确需要用户补充什么事实。

## 七、我的通知设计取向

PushPlus不应该追求“覆盖所有行情”，也不应该追求“每天固定收到很多条”。更合适的目标是**提高有限注意力的边际收益**。

因此：

- 宁可漏掉普通涨跌，也不要把用户训练成忽略微信；
- 对真正影响下一步判断的事件，宁可晚间发送，也不因为时段而压制；
- 不把单一涨跌幅直接包装成交易动作；
- 不把“系统有新数据”误写成“用户需要知道”；
- 不因为一个事件来自海外就降低优先级，也不因为它来自持仓ETF就自动提高优先级；
- 通知之后如果没有明确“现在怎么做”，通常说明这条消息本身还不够有价值。

## 八、执行边界

通知记录继续使用既有生命周期和去重机制。用户确认的真实成交继续通过正式账户事实/成交同步链处理，不从最终持仓反推成交。

通知模块不得修改MASTER、扩大交易权限、创建金额档或自动下单。市场事件负责提高注意力和触发重新评估；真正的交易动作仍严格执行MASTER买入/卖出链。

底层仍复用既有A股、overseas、US行情采集链；它们只是数据路由，不是用户可见通知分类。系统事件、A股事件、收盘账户提醒和正式决策重评由现有 `.github/workflows/decision-notification.yml` 承载；美股数据事件由 `.github/workflows/us-extended-hours-pulse.yml` 承载；日、韩、台、港数据事件由 `.github/workflows/overseas-preopen-pulse.yml` 承载。
