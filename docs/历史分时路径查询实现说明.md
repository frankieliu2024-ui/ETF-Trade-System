# 历史分时路径查询实现说明

> 本文是实现说明，不是第五个规范域，不产生交易规则或通知资格。数据资格、Point-in-Time、provider与时点规则仍以 `ETF与市场监测数据接口使用规范.md` 为唯一规范来源。

## 目的

当正式分析需要回答“两个正式节点之间发生了什么”，尤其是“A股午间休市期间日韩/亚太市场是否修复、恶化或反转”时，如果仓库没有恰好保存该边界时点的 `overseas_context` 快照，不得直接把它表述为关键数据缺口。

应先调用仓库已有历史分时能力恢复客观价格路径：

```bash
python scripts/query_intraday_history.py \
  --objects N225,KOSPI \
  --date YYYY-MM-DD \
  --start-beijing 11:30 \
  --end-beijing 13:00
```

默认使用 Yahoo Chart 5分钟bar作为历史路径恢复源；结果必须保留真实时间戳并按北京时间筛选。对于当前实时主源不是Yahoo的对象，这一路径只用于历史客观路径恢复/交叉验证，不改变实时provider优先级。

## 强制执行顺序

涉及“午休期间、两个节点之间、某段时间内、从A时点到B时点”的跨市场路径判断时：

1. 先检查是否已有当时正式快照；
2. 若没有，但已验证历史分时接口覆盖该对象，则调用历史分时查询；
3. 只有正式快照和可用历史分时都无法提供事实时，才可写“数据不足”；
4. 历史分时只恢复客观市场事实，不得伪造“当时ChatGPT/系统一定形成了某个判断”；
5. 交易结论仍按“外部结构 → 本地传导 → ETF自身反馈 → 机会判断”进入MASTER正式决策链。

## 当前适用对象

当前helper复用 `scripts/multi_source_market.py` 已有 Yahoo Chart 5分钟能力，支持：N225、KOSPI、TWII、HSTECH、NDX、SOX。对象是否具有实时正式资格及其实时主备源仍以机器配置和数据规范为准。
