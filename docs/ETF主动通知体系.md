# ETF主动通知体系

> 本文是ETF系统主动通知的唯一人类可读运行规范。它不是交易规则，不生成风险许可、生命周期、金额或买卖动作；正式交易权限仍唯一来自 `ETF规则_MASTER.md`。底层实现以当前 `main` 的通知脚本、行情上下文和 `data/state/notification_center.json` 为准。

最后更新：2026-08-28

## 1. 最高原则

PushPlus不是行情播报器，也不是GitHub运行日志出口。主动通知只判断一个问题：

**这个新事实是否足以改变我们的注意力排序、风险传导理解、候选比较、持仓风险收益或下一节点准备？**

通知资格不按“A股 / 美股 / 亚太”划分。市场归属只用于数据路由、交易阶段、provider时点和传导解释。任何当前正式监测对象——正式指数、全部持仓ETF和观察ETF、账户确认底仓个股、以及已经由具体ETF/行业假设条件调用的个股——只要满足通知价值条件，都可以主动通知。

通知层采用“召回优先但不播报噪声”的偏好：在无法同时保证高召回和极低消息量时，宁可多推送少量可能最终无交易价值的结构事件，也不要依靠过高阈值长期静默。控制消息密度优先依靠事件合并、去重、冷却和实质升级识别，而不是不断提高触发门槛。

## 2. 用户可见一级标题

- `【市场异动】`：开盘异常、快速重定价、极端波动、方向反转、显著分化，以及未来经真实CASE证明具备同等价值的市场事件；
- `【收盘总结】`：固定信息完成节点的高信息密度总结，标题后半句直接指出最重要的新事实；
- `【观察机会】`：唯一主候选实质改变注意力排序并进入观察机会；
- `【Trial机会】`：正式完整买入链已经形成Trial机会；
- `【Confirm机会】`：正式完整买入链形成Confirm机会且新增资本仍有效率；
- `【机会失效】`：此前观察/Trial/Confirm假设实质失效或唯一主候选发生有意义切换；
- `【持仓动作】`：正式判断要求明确合法份额降低风险或全部退出；
- `【风险许可】`：禁止新增 / 允许Trial / 允许Confirm发生实质切换；
- `【成交确认】`：真实成交需要确认、归因或补充明细；
- `【账户确认】`：持仓数量、现金或收盘账户事实需要确认；
- `【系统阻塞】`：真实生产故障已经影响当前/下一有效交易节点，且自动修复到达安全边界；
- `【判断恢复】`：此前因关键数据或系统条件暂缓的正式判断，在条件恢复后可继续处理。

统一发送层负责市场标题归一：旧生成器即使暂时产生 `【异动提醒】`，发送前也必须转为 `【市场异动】`。内部event_type可以更细，但不得把机器内部名称直接作为用户标题。

## 3. 市场价值事件：五类触发

### 3.1 开盘异常

开盘本身不触发。明显跳空、开盘后的强化/衰减或有意义横截面分化才触发。实际开盘价相对前收是已经发生的session事实；只要同一交易日事实仍可可靠恢复，不得因为GitHub首个pulse延迟、价格随后回落或修复而抹掉。晚到的通知应明确属于恢复事实，不能伪装成刚刚发生。

当前开盘注意力参考：A股核心指数约0.8%、监测ETF约1.5%、ETF横截面差约2个百分点；美股REGULAR优先纳斯达克100指数（NDX）和费城半导体指数（SOX）直接指数，约1%或二者分化约1个百分点；日、韩、台、港正式指数约0.8%。这些值只控制注意力，不属于MASTER。

### 3.2 快速重定价

强调速度而不是全天幅度。当前统一异动引擎参考：A股指数/ETF、亚太正式指数、美股核心指数或扩展时段核心代理，相邻有效脉冲20分钟内绝对变化约0.8%；账户/条件个股约1.5%。没有可靠相邻脉冲时不得用日内高低点伪造“20分钟急涨急跌”。

### 3.3 极端波动

当前统一异动引擎参考：A股正式指数约±2.0%，监测ETF约±3.0%，账户/条件个股约±4.0%；美股REGULAR核心正式指数、扩展时段核心代理和亚太正式指数约±1.5%，美股条件个股约±4.0%。这些只是注意力阈值。

### 3.4 方向反转

价格先形成足够大的单向日内幅度，随后明显回吐或修复，使原先的单向强弱解释可能失效。当前参考：A股指数约1.2%的先行幅度、ETF约2.0%、账户个股约3.0%；亚太和美股核心正式指数约1.2%。只有存在可靠当日OHLC/path证据时使用；不同交易阶段不得拼接伪造反转。

### 3.5 显著分化

必须存在合理比较关系。当前参考：A股核心指数差约1.5个百分点、监测ETF横截面约3个百分点、美股REGULAR的NDX/SOX或扩展时段QQQ/SOXX约1个百分点、日韩台港主要指数约1.5个百分点。不得把无可比关系的两个资产仅因涨跌差大定义为分化。

## 4. 防遗漏与运行恢复

1. **执行时刻遗漏**：已经成为可验证session事实的开盘、收盘或路径事件，不应因GitHub错过狭窄分钟窗口而永久消失；恢复后按真实事实补发并注明时点。
2. **候选饿死**：一次pulse同时出现多个有价值事件时，已发送/已管理的最高分候选不得阻塞其他未发送候选；按价值排序寻找最高未管理候选。
3. **过度去重**：同一对象、同一方向、同一事件族可在幅度实质升级时追加一次；当前升级参考为至少增加0.5个百分点，且达到原幅度约35%的增强要求中的较高者。
4. **阶段误用**：美股REGULAR优先NDX/SOX；PRE_MARKET/POST_MARKET使用QQQ/SOXX等可交易代理。直接指数健康时，代理不能抢占现金盘正式指数语义。
5. **路径证据未消费**：context已有OHLC/5分钟现金盘path时必须用于方向反转和收盘路径总结，不能只看最后价。
6. **脉冲缺口**：快速重定价仍要求真实相邻脉冲；漏调度导致间隔超过20分钟时不能伪造“20分钟异动”，但可用真实OHLC/path识别开盘异常、极端波动或方向反转。
7. **数据时点倒挂**：市场/provider时点不得晚于通知实际生成时点。统一发送层允许最多2分钟时钟偏差，超过则拒绝发送。
8. **固定节点漏发**：A股verified close在同一交易日15:00以后允许延迟补发；亚太主要市场收盘总结优先服务A股尾盘，但允许在事实仍有效时恢复；美股现金盘收盘总结在同一POST_MARKET阶段允许恢复。
9. **US收盘双入口但单事实**：美股固定收盘总结主入口仍是 `US extended-hours pulse`；现有 `Overseas pre-open pulse` 也调用同一个幂等 `send_us_session_summary.py` 作为调度兜底，并增加北京时间04:15、04:30两个独立调度槽。主US pulse正常时不会重复发送；若其在16:05 ET后漏调度，兜底应优先在收盘后约15—30分钟恢复，而不是等到北京时间07:00。
10. **workflow failure无直接通知权**：workflow failure guard只负责诊断、首次瞬态/持久化失败重跑一次，以及严格allowlist内的安全回滚。无法自动处理时仅记录diagnostic；只有后续self-healing确认故障已经持续并实际影响当前/下一有效交易节点，才获得 `【系统阻塞】` 的用户打断权限。
11. **持久化失败先重试**：commit/rebase/push等状态持久化失败属于运行基础设施问题。首次失败先自动重跑一次；若行情事实已经成功取得且未阻塞当前/下一交易节点，不得发送用户通知。

## 5. 固定与条件型通知触发矩阵

| 一级标题 / 事项 | 明确触发条件 | 时点 / 新鲜度 | 不触发的典型情况 |
|---|---|---|---|
| `【市场异动】` | 当前正式监测对象满足五类价值事件之一，并通过有效阶段、去重和升级检查 | 使用真实provider/市场时点；补发注明原事实时点 | 普通涨跌、旧行情重放、普通创新高/低、普通排名变化 |
| `【收盘总结】` A股 | 当日正式A股close已形成且数据完整 | 优先15:00后即时；同日verified close允许延迟补发，价格有效时点固定15:00 | 未形成正式close、非交易日 |
| `【收盘总结】` 亚太主要市场 | 日韩台主要市场已形成当日有效收盘结果；HSTECH未收盘时明确标记盘中 | 优先服务A股尾盘；调度/provider延迟可恢复 | 数据不是当日有效市场日期 |
| 亚太香港收盘后更新 | HSTECH实质改变此前区域判断，或主总结缺失 | 香港收盘后同日可恢复 | 香港最终结果没有新增判断价值 |
| `【收盘总结】` 美股 | NDX与SOX同一现金盘交易日数据有效；直接指数不可用才明确降级QQQ/SOXX | 现金盘收盘后；主US pulse优先，现有overseas pulse北京时间04:15/04:30提供同一幂等入口的调度兜底 | 数据日期/阶段不一致 |
| `【观察机会】` | 最新正式决策相对上一正式决策出现实质候选/机会变化并进入观察机会 | 最新正式决策 | 静态观察重复 |
| `【Trial机会】` | 正式买入链完成，机会状态进入Trial且风险许可允许，金额按MASTER | 最新正式决策 | 仅行情上涨/研究信号 |
| `【Confirm机会】` | 正式买入链完成，机会状态进入Confirm且新增资本仍有效率 | 最新正式决策 | 仅因盈利/上涨 |
| `【机会失效】` | 原观察/Trial/Confirm假设实质失效或候选有意义切换 | 最新正式决策 | 普通波动但假设未变 |
| `【持仓动作】` | 正式持仓动作变化为明确合法份额降低风险或全部退出 | 最新正式决策 | 机械技术指标变化 |
| `【风险许可】` | 禁止新增 / 允许Trial / 允许Confirm实质切换 | 正式风险边界事实 | 风险数值变化但许可未变 |
| `【成交确认】` | execution reconciliation需要确认成交/归因/部分执行 | 真实账户和决策事实 | 已确认成交 |
| `【账户确认】` | 需要用户确认未解释持仓/现金或缺失收盘账户事实 | 真实账户时点 | 纯mark-to-market变化 |
| `【系统阻塞】` | self-healing确认故障重复/持续且已经影响当前或下一有效交易节点，自动恢复已到安全边界 | 即时 | 单次workflow失败、单次commit/rebase/push失败、维护成功、已自动恢复 |
| `【判断恢复】` | 此前因关键条件暂缓的正式判断恢复且仍有待处理事项 | 即时 | 无待处理交易判断的后台恢复 |

## 6. 通知优先级与防刷屏

优先级仅用于注意力调度：正式交易动作 > 成交/账户确认 > 结构性市场异动 > 固定收盘总结 > 仅在真正阻塞交易节点时的系统消息。

同一行情演化同时命中多个事件时尽量合并为一条高信息量通知。同一对象、同一方向的快速重定价当前采用30分钟冷却；极端波动、方向反转、显著分化同日默认不重复，但满足实质升级标准可以再次通知。一次pulse有多个候选时，已管理候选必须让位给下一最高未管理候选。

## 7. Point-in-Time与数据口径

- 已结束交易时段的旧行情不得因workflow重跑重新包装成当前异动；补发必须明确原事实时点；
- A股15:00价格有效时点与其后provider查询时间分开；
- 美股REGULAR、PRE_MARKET、POST_MARKET严格分开；REGULAR优先NDX/SOX，PRE/POST使用QQQ/SOXX等可交易代理；
- 市场/provider时点不得晚于通知生成时点超过2分钟；
- 跨市场信息固定按 `外部结构 → 本地传导 → ETF自身反馈 → 机会判断` 使用，不反向污染历史决策时点。

## 8. 统一正文与PushPlus展示要求

市场异动通知优先采用四段式：

`核心结论 → 对ETF系统的影响 → 当前动作 → 数据与边界`

核心结论直接给事件类型、中文名称（代码）、关键幅度和真正改变判断的路径；不重复两遍相同数字。对象专属说明只能在对应对象事件出现。

收盘总结必须体现日内路径，至少回答：开盘如何、盘中高低点/修复回撤如何、首小时/中段/尾段如何演化、最终收在日内区间什么位置，以及这对下一A股节点意味着什么。只报最终涨跌幅不合格。

workflow诊断不允许直接变成PushPlus。真正的系统通知只能由已证明影响交易节点的self-healing状态生成，且不得把Run ID、内部步骤名、文件名、diagnostic分类等机器日志作为主体。`【系统阻塞】`正文只回答：阻塞了什么、影响哪个交易节点、系统已做什么、用户是否需要行动、下一次复核是什么。

Trial/Confirm必须明确风险许可、机会状态、金额档、资金来源、失效条件和最近复核节点；持仓动作必须给明确合法份额；账户/成交确认必须明确用户需要补充什么事实。

PushPlus微信渠道存在平台层展示模板：ETF系统通过API传入的业务 `title` 会显示在PushPlus模板业务字段中，但微信最外层模板名称由PushPlus/微信服务号模板决定，不属于ETF系统可控字段。不得为了改变微信外层模板名称另建平行通知链。

## 9. 运行入口

- 统一通知状态：`data/state/notification_center.json`
- 统一事件/账户/正式决策通知：`scripts/notification_center.py`
- 五类市场价值事件：`scripts/send_market_shock_notification.py`
- A股/亚太节点总结：`scripts/send_regional_session_summary.py`
- 美股现金盘节点总结：`scripts/send_us_session_summary.py`
- 通知公共模板、用户标题归一和时点保护：`scripts/market_notification_common.py`
- 工作流失败分类/自动重试：`scripts/workflow_failure_guard.py`
- A股通知workflow：`.github/workflows/decision-notification.yml`
- 亚太行情与通知workflow：`.github/workflows/overseas-preopen-pulse.yml`
- 美股行情与通知workflow：`.github/workflows/us-extended-hours-pulse.yml`
- 跨市场心跳恢复：`.github/workflows/self-healing-watchdog.yml`

底层workflow可以按市场拆分，但不得形成多套用户通知规则。

## 10. 维护要求

本文是主动通知唯一人类可读规范。任何改变通知对象、五类事件定义、注意力阈值、一级标题、固定总结节点、正式机会/账户/系统通知条件、去重/冷却、Point-in-Time边界、调度兜底或PushPlus正文模板的生产修改，都必须同步更新本文并执行系统一致性检查。

真实运行阶段优先复盘三类CASE：收到但无独立价值的消息；应该收到但遗漏的消息；收到后真正改变注意力/判断/执行质量的消息。当前阶段优先降低系统性漏报，再根据真实噪声反馈收敛，而不是预先把阈值调得过严。
