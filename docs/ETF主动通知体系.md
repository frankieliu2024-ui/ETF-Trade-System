# ETF主动通知体系

> 本文是ETF系统主动通知的唯一人类可读运行规范。它不是交易规则，不生成风险许可、生命周期、金额或买卖动作；正式交易权限仍唯一来自 `ETF规则_MASTER.md`。底层实现以当前 `main` 的通知脚本、行情上下文和 `data/state/notification_center.json` 为准。

最后更新：2026-08-27

## 1. 最高原则

PushPlus不是行情播报器，也不是GitHub运行日志出口。主动通知只判断一个问题：

**这个新事实是否足以改变我们的注意力排序、风险传导理解、候选比较、持仓风险收益或下一节点准备？**

通知资格不按“A股 / 美股 / 亚太”划分。市场归属只用于数据路由、交易阶段、provider时点和传导解释。任何当前正式监测对象——正式指数、全部持仓ETF和观察ETF、账户确认底仓个股、以及已经由具体ETF/行业假设条件调用的个股——只要满足通知价值条件，都可以主动通知。

每条主动通知至少满足：事实是新的；具有独立关注或行动价值；不通知会降低下一步判断或执行质量。否则只后台记录。

## 2. 用户可见一级标题

用户可见标题按“为什么收到这条消息”分类，而不是按市场分类：

- `【异动提醒】`：开盘异常、快速重定价、极端波动、方向反转、显著分化，以及未来经真实CASE验证具备同等价值的市场事件；
- `【收盘总结】`：固定信息完成节点的高信息密度总结，标题后半句应直接指出当天最重要的新事实；
- `【观察机会】`：唯一主候选进入值得持续准备的观察状态，且实质改变注意力排序；
- `【Trial机会】`：正式完整买入链已形成Trial机会；
- `【Confirm机会】`：正式完整买入链已形成Confirm机会；
- `【机会失效】`：此前观察/Trial/Confirm假设实质失效，或主候选发生有意义切换；
- `【持仓动作】`：正式判断要求明确合法份额降低风险或全部退出；
- `【风险许可】`：禁止新增 / 允许Trial / 允许Confirm发生实质切换；
- `【成交确认】`：真实成交事实需要用户确认、归因或补充成交明细；
- `【账户确认】`：真实持仓数量、现金或收盘账户事实需要用户确认；
- `【系统阻塞】`：真实生产故障已经影响或将直接阻塞当前/下一有效交易节点，且自动修复到达安全边界；
- `【判断恢复】`：此前因关键数据或系统条件暂缓的正式判断，在条件真正恢复后可以继续处理。

内部event_type可以更细，但不得把机器内部名称直接当成用户标题体系。

## 3. 市场价值事件：五类触发

### 3.1 开盘异常

开盘本身不触发。只有明显跳空、方向、开盘后快速确认或横截面分化足以改变注意力排序时才触发。

当前注意力参考：A股核心指数绝对涨跌约1%、监测ETF约2%或ETF横截面差约2.5个百分点；美股QQQ/SOXX约1%或二者分化约1个百分点；日、韩、台、港正式指数约1%。不同市场不要求同步开盘，谁先产生有价值的新事实，谁先通知。

### 3.2 快速重定价

强调速度而不是全天幅度。指数/ETF当前参考为相邻有效脉冲20分钟内绝对变化约1%。个股天然波动更高，使用更高注意力阈值；没有可靠相邻脉冲时不得用日内高低点伪造“20分钟急涨急跌”。

### 3.3 极端波动

强调绝对幅度进入非常规区间。当前参考：A股正式指数约±2.5%，监测ETF约±4%，账户/条件个股约±5%；美股核心代理和亚太正式指数约±2%，美股条件个股采用更高阈值。

### 3.4 方向反转

价格先形成足够大的单向日内幅度，随后大幅回吐或修复，使原来的单向强弱解释可能失效。只有存在可靠当日路径/OHLC证据时使用；美股现金盘和扩展时段不得跨阶段拼接反转。

### 3.5 显著分化

用于识别“单一市场强/弱概括已经失效”。必须存在合理比较关系，例如核心指数之间、ETF横截面、QQQ与SOXX、日韩台港之间、或已经建立独立传导假设的对象与其基准。不得把无可比关系的两个资产仅因涨跌差大就定义为分化。

上述所有阈值只控制注意力，不属于MASTER交易规则，也不能直接产生买卖动作。

## 4. 固定与条件型通知触发矩阵

| 一级标题 / 事项 | 明确触发条件 | 时点 / 新鲜度 | 不触发的典型情况 |
|---|---|---|---|
| `【异动提醒】` | 当前正式监测对象满足五类价值事件之一，且通过去重/当前有效阶段检查 | 对应市场当前有效阶段；相邻脉冲事件使用真实provider时点 | 普通涨跌、旧行情重放、普通创新高/低、普通排名变化 |
| `【收盘总结】` A股 | 当日正式A股close已形成且数据完整 | 价格有效时点15:00；provider补查时点单列 | 未形成正式close、非交易日 |
| `【收盘总结】` 亚太主要市场 | 北京时间14:35—14:55，日/韩/台当日有效收盘结果可用；HSTECH如仍交易明确标记盘中 | 服务A股最后约20分钟 | 数据不是当日有效市场日期 |
| 亚太香港收盘后更新 | HSTECH较14:35主总结变化约≥1个百分点、区域判断实质改变，或14:35主总结因故缺失 | 16:05—16:30左右 | 香港收盘没有改变此前判断 |
| `【收盘总结】` 美股 | QQQ/SOXX同一现金盘交易日数据有效，进入POST_MARKET 16:05—16:30 ET | 必须包含现金盘日内路径；盘后变化另算扩展时段 | QQQ/SOXX数据不完整或market date不一致 |
| `【观察机会】` | 最新正式决策相对上一正式决策出现实质候选/机会变化并进入观察机会 | 正式决策形成后，当前代码要求事件不超过45分钟 | 静态观察状态重复出现 |
| `【Trial机会】` | 正式买入链完成，机会状态新进入Trial机会且风险许可允许，金额按MASTER固定档位 | 正式决策形成后不超过45分钟；行情依据必须可追溯 | 仅行情上涨、仅研究信号、风险许可不允许 |
| `【Confirm机会】` | 正式买入链完成，机会状态新进入Confirm机会且新增资本仍有效率 | 同上 | Trial未验证、仅因盈利/上涨、风险许可关闭 |
| `【机会失效】` | 原观察/Trial/Confirm假设在最新正式决策中实质失效，或候选发生有意义切换 | 最新正式决策 | 普通波动但假设未变 |
| `【持仓动作】` | 最新正式持仓动作从上一判断变化为明确合法份额降低风险或全部退出 | 最新正式决策 | “没有机械退出触发”本身不通知 |
| `【风险许可】` | 禁止新增 / 允许Trial / 允许Confirm发生实质切换 | 最新正式决策/正式风险边界事实 | 风险数值变化但许可未变 |
| `【成交确认】` | execution reconciliation进入CONFIRMATION_REQUIRED，存在待确认成交/归因/部分执行 | 以真实账户和决策事实为准 | 已确认且已归因成交 |
| `【账户确认】` 未解释账户变化 | 30分钟内存在未对账持仓数量变化，或未解释现金变化绝对值≥10元 | 账户事实不超过30分钟 | 总资产、市值、浮盈亏等纯mark-to-market变化 |
| `【账户确认】` 收盘账户 | A股正式交易日15:20任务触发时，仍没有15:00之后可确认的最终账户事实 | 北京时间15:20左右 | 已有收盘后有效账户事实、非交易日 |
| `【系统阻塞】` | self-healing要求ESCALATE，或当前main的workflow诊断为ESCALATE_WITH_DIAGNOSTIC，且影响交易判断/下一节点 | 事件发生后即时 | 普通维护成功、自动修复成功、旧失败重放 |
| `【判断恢复】` | 此前正式判断因关键行情/账户/决策信息不完整而暂缓，之后E2E条件真实恢复且有待继续判断 | 恢复事件形成后即时 | 普通后台任务恢复但没有待处理交易判断 |

## 5. 通知优先级

优先级不是隐藏交易评分，只用于防止高价值结论被低层证据淹没：

1. 正式交易动作：Trial机会、Confirm机会、持仓动作、风险许可、机会失效；
2. 用户事实确认：成交确认、账户确认；
3. 结构性市场事件：异动提醒；
4. 固定节点总结：收盘总结；
5. 系统阻塞/判断恢复：仅在真正影响交易节点时占用注意力。

同一行情演化同时满足多个市场事件时，应尽量合并成一条高信息量 `【异动提醒】`。若市场异动随后已经形成正式Trial/Confirm/持仓动作，后续优先通知正式结论，而不是继续重复低层行情证据。

## 6. 防刷屏与Point-in-Time

- 同一对象、同一方向的快速重定价采用45分钟冷却；
- 极端波动、方向反转、显著分化在同一市场日、同一对象/结构、同一方向默认只主动通知一次；
- 快速重定价升级为极端波动或方向反转，可以追加一次；
- 已结束交易时段的旧行情不得因workflow重跑重新包装成当前异动；
- A股15:00收盘价格有效时点与15:00后的provider查询时点必须分开；
- 美股REGULAR、PRE_MARKET、POST_MARKET严格分开；扩展时段只相对最近现金盘收盘解释；
- 跨市场信息按 `外部结构 → 本地传导 → ETF自身反馈 → 机会判断` 使用，不反向污染历史决策时点。

## 7. 统一正文要求

每条有实质内容的PushPlus优先回答：

`发生了什么 → 路径/证据如何演化 → 为什么值得现在知道 → 对风险传导/候选/持仓意味着什么 → 现在怎么做 → 数据时点 → 解释边界`

Trial/Confirm进一步必须明确风险许可、机会状态、金额档、资金来源、失效条件和最近复核节点；持仓动作必须给明确合法份额；账户/成交确认必须明确用户需要补充什么事实。

## 8. 运行入口

- 统一通知状态：`data/state/notification_center.json`
- 统一事件/账户/正式决策通知：`scripts/notification_center.py`
- 五类市场价值事件：`scripts/send_market_shock_notification.py`
- A股/亚太节点总结：`scripts/send_regional_session_summary.py`
- 美股现金盘节点总结：`scripts/send_us_session_summary.py`
- 通知公共模板：`scripts/market_notification_common.py`
- A股通知workflow：`.github/workflows/decision-notification.yml`
- 亚太行情与通知workflow：`.github/workflows/overseas-preopen-pulse.yml`
- 美股行情与通知workflow：`.github/workflows/us-extended-hours-pulse.yml`

底层workflow可以按市场拆分，但不得因此形成三套用户通知规则。

## 9. 维护要求

本文是主动通知的唯一人类可读规范。任何会改变以下任一事项的生产修改，都必须同步更新本文：通知对象、五类事件定义、注意力阈值、一级标题、固定总结节点、正式机会/账户/系统通知条件、去重/冷却、Point-in-Time边界或PushPlus正文模板。

`notifications/README.md` 只保留实现目录说明并指向本文，不再复制整套规则。通知相关代码修改必须执行系统一致性检查；真实运行3—5个完整交易日后，应优先根据实际PushPlus CASE调整重复通知、漏通知和注意力阈值，而不是继续凭想象增加事件类别。
