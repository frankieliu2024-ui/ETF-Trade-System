## 一、固化的治理经验

### 1. 生产者与消费者必须成对验收

任何修复都不能只验证 producer 已成功。必须同时确认下游 consumer 实际执行、消费的是同一份 current main 事实，并完成关键投影回读。workflow 总体成功但关键步骤 skipped，不得视为闭环。

本次对应经验：手动 close 已能生成收盘复核上下文，但 E2E consumer 仍因 query_context 条件被跳过；真正闭环要求 producer 与 E2E rebuild 同时成功。

### 2. 入口条件必须覆盖完整业务路径

入口身份、手动/自动模式、节点意图和下游条件必须在整条 workflow 中保持一致。手动 close 的合法性不能只在 session gate 识别，还必须传递到复核 producer 和 E2E consumer；自动入口的交易日、节点和 SKIP 合同不得因此放松。

### 3. workflow 成功、artifact 成功和 canonical 状态成功必须分开

一致性 workflow 的临时报告和 artifact 是本次审计证据；canonical `data/state/system_consistency.json` 是最近一次生产验收持久化状态。两者不能互相冒充，也不能让只读审计 workflow 直接增加第二 writer。正式报告必须明确 checked commit、run id、生成时间和持久化边界。

### 4. 长时段修复必须以证据矩阵控制范围

每轮修复开始前登记：问题、证据、唯一 owner、影响边界、验收条件和停止条件。发现相邻问题时先判断是同一根因、同一 owner、同一链路，只有满足时才并入当前修复；否则建立新的可复现问题，避免过度收敛或无限扩张。

### 5. Issue 关闭以交付物矩阵为准

PR 合并只证明代码变更已集成，不证明 Issue 的全域交付物全部完成。Issue 关闭前必须逐项回读：合同矩阵、读写 owner 清单、legacy 路径判定、未来对象回归、收盘复核 E2E、通知失败/恢复 E2E、三类任务真实运行和合并后 main 验收。
