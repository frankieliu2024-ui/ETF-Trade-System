# 市场行情查询路由与全球时点规则 V1.0

> 实现状态：`scripts/market_quote_router.py` 为唯一无网络行情路由入口；当前上下文与收盘复盘只消费其生成的路由视图。

## 定位

本文件定义“用户查询最新行情”时的数据选择逻辑，不改变交易规则，不产生买卖动作。

核心原则：行情系统24小时可查询，但输出必须服从对象所在市场的真实交易阶段。

## 覆盖市场

- 中国大陆（A股）
- 中国香港（港股）
- 中国台湾（台股）
- 美国（美股）
- 日本（日股）
- 韩国（韩股）

所有输出必须同时包含：

1. 标的名称（中文）
2. 代码
3. 数据时间（北京时间）
4. 本地市场时间
5. 市场阶段（PRE_MARKET / REGULAR / POST_MARKET / CLOSED）
6. 数据来源

禁止只显示自然日期，不显示具体时点。

## 通用查询逻辑

行情查询优先级：

1. 当前市场实时有效行情
2. 当前市场扩展时段行情
3. 最近正式交易日收盘行情
4. 明确标注的数据代理

禁止：

- 实时交易期间返回旧收盘并称为“最新行情”；
- 使用workflow执行时间冒充行情时间；
- 混淆不同市场交易日。

## 美国市场

美国市场必须区分：

- PRE_MARKET：美东04:00-09:30
- REGULAR：美东09:30-16:00
- POST_MARKET：美东16:00-20:00
- OFF_SESSION

规则：

美股REGULAR阶段：返回实时现金盘数据。

美股PRE_MARKET阶段：返回盘前价格，同时保留上一正式现金盘收盘价作为基准。

美股POST_MARKET阶段：返回盘后价格，同时标注非现金盘。

OFF_SESSION：返回最近正式收盘价。

扩展时段价格只作为前置信号，不得直接等同正式指数。

## 中国香港

恒生科技指数等港股对象：

交易时间按香港市场时区判断。

开盘期间返回最新交易数据；收盘后返回当日收盘；开盘前返回上一交易日收盘。

## 日本、韩国、台湾

分别使用东京、首尔、台北本地交易时间。

必须根据：

- market_timezone
- market_phase
- as_of_local
- as_of_beijing

共同判断。

## 中国大陆A股

A股：

- 09:15-09:25 集合竞价
- 09:30-11:30 连续交易
- 13:00-15:00 连续交易
- 15:00后正式收盘

15:00后返回当日正式收盘，不使用盘后补采价格替代。

## ETF和个股

指数、ETF、个股统一遵循市场阶段逻辑。

例如：

- 美股个股盘后：返回盘后价格；
- 美股个股盘前：返回盘前价格；
- 美股休市：返回上一交易日收盘。

## ETF系统调用规则

当用户请求：

“最新美股行情”
“最新海外行情”
“某股票行情”

系统必须先判断：

对象 → 市场 → 时区 → 市场阶段 → 数据源 → 输出。

不得固定读取单一状态文件。

## 决策边界

行情查询解决“当前事实是什么”。

交易判断仍必须经过：

行情事实 → 本地传导 → ETF自身结构 → MASTER规则 → 交易决策。

海外行情不得绕过A股本地验证直接生成ETF动作。


## 工程实现边界

统一调用链为：用户/上下文请求 → `market_quote_router` → 市场识别 → 本地时区阶段判断 → 已生成状态中的合格来源选择 → 中文化输出。路由层不发起provider请求，不生成交易动作，也不改变CURRENT；采集workflow仍负责生成 `CURRENT`、`overseas_context.json` 和 `us_extended_hours_context.json`，它们是事实状态源，不是用户最终输出入口。

`decision_context.json`、`query_context.json` 和 `review_context.json` 中的行情摘要必须使用 `market_quote_router` 生成的视图。内部阶段字段仅供机器审计；用户展示使用“美股交易中/美股盘前/美股盘后/美股休市中”等中文状态，并同时显示中文数据性质和北京时间。

美国扩展时段按纽约本地时间严格解释：04:00–09:30为盘前，09:30–16:00为现金盘，16:00–20:00为盘后，20:00–04:00为休市。北京时间05:00在夏令时对应纽约17:00，因此应显示“美股盘后”，不能按“美股休市中”处理；若用户需要休市测试，应使用北京时间08:00之后（夏令时）或09:00之后（冬令时）的相应时点。
