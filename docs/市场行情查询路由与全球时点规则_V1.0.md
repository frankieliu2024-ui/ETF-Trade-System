# 市场行情查询路由与全球时点规则 V1.0

> 实现状态：`scripts/market_quote_router.py` 为ETF系统内部唯一无网络行情路由入口；当前上下文与收盘复盘只消费其生成的路由视图。

## 定位

本文件定义“用户查询最新行情”时的数据选择逻辑，不改变交易规则，不产生买卖动作。

核心原则：普通临时公开行情查询由ChatGPT自主选择最有效的数据来源；ETF系统一旦被调用，其内部仍必须服从统一行情路由、真实市场阶段和数据质量边界。正式ETF分析不得用普通网页行情替代canonical CURRENT或其他正式系统事实。

## 覆盖市场

- 中国大陆（A股）
- 中国香港（港股）
- 中国台湾（台股）
- 美国（美股）
- 日本（日股）
- 韩国（韩股）

所有输出必须同时包含：

1. 标的名称（中文）
2. 代码
3. 数据时间（北京时间）
4. 本地市场时间
5. 市场阶段（PRE_MARKET / REGULAR / POST_MARKET / CLOSED）
6. 数据来源

禁止只显示自然日期，不显示具体时点。

## 通用查询逻辑

行情查询优先级：

1. 当前市场实时有效行情
2. 当前市场扩展时段行情
3. 最近正式交易日收盘行情
4. 明确标注的数据代理

禁止：

- 实时交易期间返回旧收盘并称为“最新行情”；
- 使用workflow执行时间冒充行情时间；
- 混淆不同市场交易日。

## ChatGPT自主来源路由

普通临时公开行情问题，例如“某股票最新行情”“某指数现在多少”“某ETF今天涨多少”，默认优先使用联网搜索取得当前公开事实。ChatGPT应自主比较时效、来源可靠性、market phase、可审计性和回答成本，不要求用户先提供证券代码，也不要求用户指定“联网”或“ETF系统”。Web优先不等于采用第一个搜索结果；必要时应优先交易所或可靠财经源并进行交叉核验。

以下情况优先或同时调用ETF系统：

- 对象属于正式监测、当前账户、持仓或观察体系，需要与canonical CURRENT、账户事实或生命周期保持一致；
- 正式ETF盘前、盘中、午间、盘后分析，需要Point-in-Time、统一provider时点和可审计决策证据；
- ETF系统具有明确增量能力，例如腾讯A股quote、腾讯1分钟路径、market structure、相对强弱、研究执行桥或其他正式内部证据；
- 联网结果冲突、时点不清或质量不足，需要正式provider链交叉验证；
- 用户明确指定某一来源、腾讯分钟源或ETF系统。

若普通临时查询中Web证据明显更新、更可靠，则无需为了“走系统”而触发ETF workflow。反之，若ETF系统对该对象具有更高质量或更适合正式判断的证据，应主动调用ETF系统。用户明确指定来源属于偏好/约束，但不是正常查询的必要前提。

正式ETF交易分析中，普通Web行情只能作为外部补充证据；不得把Web搜索结果冒充canonical CURRENT、账户事实或正式系统provider输出，也不得绕过系统数据降级语义生成正式交易动作。

## 美国市场

美国市场必须区分：

- PRE_MARKET：美东04:00-09:30
- REGULAR：美东09:30-16:00
- POST_MARKET：美东16:00-20:00
- OFF_SESSION

规则：

美股REGULAR阶段：返回实时现金盘数据。

美股PRE_MARKET阶段：返回盘前价格，同时保留上一正式现金盘收盘价作为基准。

美股POST_MARKET阶段：返回盘后价格，同时标注非现金盘。

OFF_SESSION：返回最近正式收盘价。

扩展时段价格只作为前置信号，不得直接等同正式指数。

## 中国香港

恒生科技指数等港股对象：

交易时间按香港市场时区判断。

开盘期间返回最新交易数据；收盘后返回当日收盘；开盘前返回上一交易日收盘。

## 日本、韩国、台湾

分别使用东京、首尔、台北本地交易时间。

必须根据：

- market_timezone
- market_phase
- as_of_local
- as_of_beijing

共同判断。

## 中国大陆A股

A股：

- 09:15-09:25 集合竞价
- 09:30-11:30 连续交易
- 13:00-15:00 连续交易
- 15:00后正式收盘

15:00后返回当日正式收盘，不使用盘后补采价格替代。

## ETF和个股

指数、ETF、个股统一遵循市场阶段逻辑。

例如：

- 美股个股盘后：返回盘后价格；
- 美股个股盘前：返回盘前价格；
- 美股休市：返回上一交易日收盘。

## ETF系统调用规则

当ETF系统查询链被调用时，系统必须先判断：

对象 → 市场 → 时区 → 市场阶段 → 数据源 → 输出。

不得固定读取单一状态文件，也不得为单次对象建立平行的内部行情入口。`scripts/query_market_object.py` 仍是ETF系统内部的单对象查询入口；其存在不代表所有普通聊天行情查询都必须先触发ETF系统。

## 决策边界

行情查询解决“当前事实是什么”。

交易判断仍必须经过：

行情事实 → 本地传导 → ETF自身结构 → MASTER规则 → 交易决策。

海外行情不得绕过A股本地验证直接生成ETF动作。


## 工程实现边界

ETF系统内部统一调用链为：系统查询/上下文请求 → `market_quote_router` → 市场识别 → 本地时区阶段判断 → 已生成状态中的合格来源选择 → 中文化输出。路由层不发起provider请求，不生成交易动作，也不改变CURRENT；采集workflow仍负责生成 `CURRENT`、`overseas_context.json` 和 `us_extended_hours_context.json`，它们是事实状态源，不是用户最终输出入口。

`decision_context.json`、`query_context.json` 和 `review_context.json` 中的行情摘要必须使用 `market_quote_router` 生成的视图。内部阶段字段仅供机器审计；用户展示使用“美股交易中/美股盘前/美股盘后/美股休市中”等中文状态，并同时显示中文数据性质和北京时间。

美国扩展时段按纽约本地时间严格解释：04:00–09:30为盘前，09:30–16:00为现金盘，16:00–20:00为盘后，20:00–04:00为休市。北京时间05:00在夏令时对应纽约17:00，因此应显示“美股盘后”，不能按“美股休市中”处理；若用户需要休市测试，应使用北京时间08:00之后（夏令时）或09:00之后（冬令时）的相应时点。
