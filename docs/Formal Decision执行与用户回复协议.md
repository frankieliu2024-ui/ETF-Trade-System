# Formal Decision执行与用户回复协议

版本：统一三入口单链 V5  
适用范围：每一次【ETF正式决策】的对话窗口运行、任务界面手动运行和系统日历自动运行。

本协议是 Formal Decision 的唯一现行执行合同。三个入口统一执行同一条生产链。交易规则、数据资格、通知服务商优先级和生产变更规则分别服从 INDEX 路由的 MASTER、数据规范、主动通知协议和生产治理协议。本协议不创建新的 workflow、producer、checker、state、writer、交易权限或通知链。

## 一、唯一目标与边界

每次运行必须基于current main已经形成的最近合法固定时段最新正式事实，形成一份完整、可审计且对象级覆盖的正式 ETF 管理判断。

判断至少覆盖：

- 风险许可、市场状态和资本环境；
- 海外与跨市场、A股内部反馈和三层监测；
- 全市场 Discovery 对象；
- 全部观察 ETF；
- 当前机会 ETF；
- 全部实际持仓及每只持仓的继续持有、追加、减持或退出判断；
- 现金、可部署现金、可释放资本和资金缺口；
- Trial/Confirm 资格、建议动作、实际新增部署和实际执行结果；
- 关键风险、改变判断的条件、信息不足、置信度和最可能出错的地方。

不得自动下单、自动调仓或改变交易权限。所有证券交易均由用户人工确认和执行。

不得消费、改写或替代【ETF系统复核】和【ETF交易复盘】的业务对象。

### Formal Decision与账户执行解耦（本次集中修复）

Formal Decision首先是独立的市场管理判断，不以账户现金、当前份额、当日委托、当日成交或可用资金作为Discovery、机会ETF、Trial、Confirm、买入、卖出、追加、减持或退出判断的准入门槛。账户事实属于后续组合映射与执行确认层：用于判断建议适用于哪些持仓、能否落地、实际数量和成交结果，不得反向否定已经由市场事实形成的决策结论。

Discovery是正式候选生成层，必须逐只进入机会资格评估；Hyperliquid是正式跨市场证据层，必须参与相关对象的方向、相对强弱、跨市场传导、拥挤和时机判断。二者不是仅用于正文解释的弱辅助信息，但也不能单独生成订单或替代风险规则。Discovery覆盖不完整或Hyperliquid时间精度不足，只降低受影响对象的覆盖范围、时点精度或置信度，不自动推出机会不存在、Trial为0或Confirm为0。

Formal Decision的用户可见正文还必须披露本次实际消费的脉冲来源边界：Discovery的最新生成时间、最新合法节点、覆盖状态和候选数量；Hyperliquid的采集时间、质量状态、观测数量和时间依据。两者应写入“判断时点与事实边界”或“数据与边界”，不得只在正文中笼统写“无映射”“无实时信号”。若Hyperliquid没有与当前对象形成直接代码映射，但存在行业、产业链或风险因子级证据，必须用一两句话说明其方向、背离或风险过滤作用；只有确实没有可消费证据时，才可写明无增量信号。

正式判断必须分别输出管理建议与执行结果。可以在账户事实不可用或滞后时形成“买入/卖出/持有/追加/减持/退出、Trial或Confirm”的市场层判断；不得因此把建议动作改写成“建议新增0元”或“建议释放0份”。“实际新增0元”“实际释放0份”只能表示本次没有确认成交，不能表示市场层没有买入或释放理由。实际持仓分析属于组合映射，不是市场决策形成的前置条件；若账户事实不可用，应披露未完成映射，但不得阻断市场层正文。


## 二、入口和唯一运行身份

入口必须依据真实触发方式识别：

| 入口 | source | entry_mode |
|---|---|---|
| 对话窗口手动运行 | CHATGPT_MANUAL_FORMAL_ANALYSIS | MANUAL_CONVERSATION |
| 任务界面手动运行 | CHATGPT_MANUAL_SCHEDULED_FORMAL_ANALYSIS | MANUAL_SCHEDULED_TASK |
| 系统日历自动运行 | CHATGPT_SCHEDULED_FORMAL_ANALYSIS | AUTOMATIC_SCHEDULED_TASK |

task_id固定为“ETF正式决策”，interaction_scenario固定为“FORMAL_DECISION”。

本次运行只建立唯一运行身份：

- task_id、task_run_id、occurrence_id；
- market_date、requested_at_beijing、runtime_now；
- source、entry_mode、interaction_scenario；
- market_phase、判断路径和判断事实边界。

Formal Decision不为本次判断新建市场事实请求、MARKET_QUOTE_REFRESH、父请求、request-bound snapshot、formal_reply_gate、query_context或decision_context。正式判断直接消费current main已经形成的最近合法固定时段事实。

不得使用历史正文、旧请求、旧门禁或旧上下文替代current main最新合法事实。completion中的request_id仅作为本次运行和交接身份，不得被解释为新的市场事实请求。

## 三、事实读取与新鲜度

必须从current main读取本次运行时已经形成的最近合法事实：

- 市场行情和市场监测；
- 账户、现金、成交和实际持仓；
- 风险与生命周期；
- Discovery、观察ETF和机会ETF；
- 与目标固定时段直接相关的海外、亚洲、商品、利率和汇率事实。

正式决策同时直接消费Hyperliquid外部事实域。Hyperliquid与A股行情、海外市场、Discovery、观察ETF、机会ETF和实际持仓并行读取、统一比较，不构成任何对象进入下一层的前置门槛。其用途限于对象级方向确认、跨市场传导、交易时机过滤、拥挤度/定价偏离和证据缺口识别；不得独立生成Trial、Confirm、金额、卖出份额或订单。Hyperliquid缺失、过时或接口降级时，只降低相关对象的外部证据强度，不阻断其他事实、正文、completion或通知链。

Hyperliquid接口未提供可靠的provider原生事件时间时，必须保留并传递本次事实的context_id、collection_started_at_utc、collection_finished_at_utc、earliest_observation_collected_at_utc、latest_observation_collected_at_utc、observation_count及各对象collected_at_beijing。采集完成时间只能作为“状态对本次运行可见的时间边界”，不得表述为事件发生时间；正式正文不得将精确采集窗口粗化为“某时段前后”。completion的fact_binding或等价事实绑定必须同时记录实际消费的Hyperliquid context_id及其最新采集完成时间，否则不得声称Hyperliquid与本次A股快照完成同节点对齐。

对每个相关ETF对象，正式判断应将Hyperliquid证据归入以下一种或多种语义：SUPPORT（支持既有假设）、CONTRADICTION（与既有假设矛盾）、TIMING_FILTER（改变入场时机质量但不单独改变方向）、NO_INCREMENTAL_VALUE（存在但未改变本轮判断）。不得把单一价格上涨、正Funding、OI增长或Premium偏离直接写成买入结论。

**正文固定表达要求：** 对每个存在Hyperliquid映射的相关对象，必须在对象条目中明确写出“关联外部资产及其代表方向”“本次可见信号（方向、拥挤度、资金费率、未平仓量、溢价或其他实际字段）”“与该ETF/A股事实的关系（支持、反向、确认、时机过滤或风险提示）”以及“因此维持、加强、削弱或改变了哪一项判断”。若最终动作未改变，必须说明具体原因，例如A股自身承接不足、外部信号与A股背离、证据质量不足或金额/风险收益尚未成立；不得仅写“Hyperliquid本次无明确增量价值”。只有完成映射、字段比较且确认不存在上述任何贡献时，才可使用该表述。

**通俗解释要求：** “方向偏强/偏弱”必须同时说明是价格或市场押注整体偏向哪一边；“拥挤度高”必须说明是否大量资金挤在同一方向、可能带来什么反转或回撤风险；“资金费率为正/为负”必须说明多空双方谁在向谁付费、它反映的是哪一方更急；“未平仓量上升/下降”必须说明市场中未结束的押注是在增加还是减少，以及与价格同向或反向时代表什么；“溢价扩大/收窄”必须说明价格相对参考价格更贵或更便宜，以及这对信号可靠性或追涨时机的影响。通俗解释必须紧跟专业术语，并进一步说明它对对应ETF的方向、时机、风险或资本比较产生了什么作用。

必须核验：

- market_phase、market_date和runtime_now；
- 各市场事实的market_data_at、provider_timestamp和captured_at_beijing；
- 各市场数据质量和PIT边界；
- A股事实是否为当前或上一交易日合法正式收盘事实；
- 海外及跨市场事实是否为本次运行前最近合法快照；
- A股、美国、日韩、港股、台湾、商品、利率和汇率等市场均按自身最近合法快照独立选择，不要求所有市场共用同一时点；
- 各市场分别按快照年龄标记正式判断、降级判断或超时判断；单一市场缺失或过时只降低该市场证据强度，不阻断其他市场、正文、completion或通知链；
- Discovery、观察ETF、机会ETF和实际持仓是否分别形成；
- 各事实是否属于最近合法固定时段。

正式决策不得把全市场事实强制压缩为一个统一快照。盘前或非交易时段应按市场分层消费事实：

- A股优先使用本次运行前最近通过质量、PIT和时点验收的合法快照；仅在该快照不存在或不合格时使用上一交易日15:00正式收盘事实；
- 海外、亚洲、商品、利率和汇率使用本次运行前最近通过质量、PIT和时点验收的合法快照；
- 不同市场必须分别披露实际行情时间、采集时间、数据性质及其与目标A股时段的先后关系；
- 某一海外市场事实缺失或过时，只降低该市场证据强度，不阻断A股判断、正文、completion或通知链；
- 运行开始后才形成的事实不得倒灌到本次判断。

盘中路径：

- 快照年龄不超过15分钟：正式判断；
- 快照年龄超过15分钟但不超过25分钟：降级判断；
- 超过25分钟：超时判断。超时只影响事实新鲜度、披露和置信度，不阻断任务、正文、completion或通知链。

收盘后路径优先使用当前交易日15:00行情边界、质量和PIT验收通过的正式收盘快照；收盘快照的采集时间距运行时间超过15分钟，不自动导致降级。

目标事实已经形成时，不得等待下一行情时段，不得新建刷新请求，不得重复派发等价刷新，不得使用旧事实补齐。

## 四、判断准入

以下条件满足即可形成对应判断路径；快照年龄不作为任务阻断条件：

1. 真实入口和运行身份已确定；
2. current main中至少一组合法市场事实、Discovery或Hyperliquid正式证据可读；账户、成交和实际持仓事实不属于市场层判断的必要准入条件；
3. 至少一组合法市场事实可读，并已按市场分层确定事实边界；
4. 快照路径已明确：正式判断、降级判断、超时判断或合格正式收盘判断；
5. Discovery、观察ETF、机会ETF和实际持仓已形成、正式确认为0，或其缺口可以在正文中明确披露；
6. 风险、生命周期、市场监测或对象层事实缺失时，仍可形成受限判断，但不得授予无法由事实支持的Trial、Confirm或资金动作结论；
7. 不存在使用历史事实、旧请求或旧上下文补齐的情况。

如果账户、成交或实际持仓核心事实不可读，Formal Decision仍须在存在合法市场事实、Discovery或Hyperliquid正式证据时形成市场层正式判断；此时只说明尚未完成组合映射和执行确认，不得伪造账户动作、实际金额、份额或成交结果。只有在不存在任何足以支撑市场层判断的合法事实时，才可记录市场判断未形成。市场分层事实、风险事实或对象层缺口本身不得阻断正文、completion或通知链。

自动运行不得因单次事实读取失败、对象层缺失、单一海外市场缺失、风险或生命周期缺失而暂停或修改后续调度；自动任务仍按既有节点继续运行。只有账户、成交和实际持仓核心事实全部不可读，且不存在任何合法市场事实，才可记录本次未形成正式判断；这不构成暂停后续自动任务的理由。若账户核心事实可读且至少一组合法A股或跨市场事实可读，必须形成受限、降级或超时正文，并在正文中披露缺口。

## 五、唯一 FINAL_CONTENT

准入后必须立即锁定本次读取到的current main固定时段事实，生成并冻结唯一 FINAL_CONTENT，不得停在“已达到准入状态”。READY 后，必须先完成业务判断并冻结唯一 FINAL_CONTENT，先发布此前冻结的同一份完整正文，再继续后置交接。后置交接不得阻断正文发布，也不得因 completion、事件、报告、通知或服务商结果暂时不可回读而重新生成正文。

正文首行必须严格为：

【ETF正式决策】YYYY-MM-DD HH:MM 正式判断

正文必须使用自然中文，并逐只覆盖current main中本次判断实际形成的全部实际持仓、观察ETF、机会ETF及Discovery对象；未形成或无法回读的对象层必须明确披露，不得补齐、写成0或假称全市场比较已完成。必须严格区分事实、判断、资格、建议动作、实际新增部署和实际执行结果。

四类对象章节必须分别保留。章节内确有两个及以上并列事项时使用一级编号 `1. `、`2. `3. `；一级事项下确有两个及以上子事项时使用二级编号 `1）`、`2）`、`3）`。Discovery、观察ETF、机会ETF和实际持仓的逐只对象列表使用连续的 `1）`、`2）`、`3）`，概述段不占对象编号；不得使用 `1.1`、`1.2`，不得把四类对象合并为一个总表。单独段落、章节说明、结论句、状态句、置信度和“最可能出错的地方”不得机械编号。若某类对象为零，仍须保留章节并写明数量和形成原因。正式发布前必须通过现行正文校验器的对象覆盖、资本竞争和编号层级检查。

正文必须明确：

- 数据时点和事实性质；
- 每只实际持仓的管理结论、理由、替代比较、可释放资本和改变条件；
- 如无交易条件：新增部署为0元，实际释放为0份，现金和持仓结构维持不变；
- 所有建议仅为管理建议，不自动下单、不自动调仓、不改变交易权限。

**0元决策的资本竞争完整性要求（不新增独立输出栏目或机会状态）：** 当本次建议新增部署为0元时，正文必须在既有【全市场机会与资本竞争】及相关候选、现金和持仓论证中，明确完成以下判断，不得只重复“风险偏高”“证据不足”“暂不追加”或“保留现金”：

1. **最近可执行候选：** 从本次运行前已经形成且通过时点、质量和身份核验的合法扫描对象中，指出距离进入完整买入链最近、证据基础最充分的候选，说明名称、代码、当前身份（Discovery、观察ETF或机会ETF）及其接近可执行的理由。候选必须来自本次合法事实；不得机械排名、强行指定候选，也不得把Discovery或观察ETF直接升级为机会ETF、Trial或Confirm。若不存在合理候选，必须明确说明“本次不存在合理的最近可执行候选”。
2. **决定性证据缺口：** 对该候选逐项说明已经具备的关键证据、尚缺的决定性证据、缺口为何影响机会资格或金额，以及什么可观察事实会补齐或证伪该缺口。不得以笼统的“等待确认”代替可证伪条件；不得把未取得的数据写成反向证据。
3. **资本替代路径：** 明确若上述决定性证据补齐，最可能替代的当前资本用途是什么（现金保留、某只现有持仓继续占资、追加现有持仓或其他合法资本用途），说明替代理由、边际风险收益、机会成本、重复暴露、资金占用、迁移成本及执行约束。若涉及现有持仓释放，必须单独说明该持仓为何可能不再胜出；资本替代比较不等于卖出决议，不得预授权卖出、假定释放份额或绕过独立卖出链。
4. **最近复核节点：** 指明最近的下一次正式决策节点或明确可验证的事件节点，并写明届时要核验的决定性事实及其可能改变的机会、金额或资本去向。不得以无期限“继续观察”作为结论。

若不存在合理候选，仍必须说明现金是否为当前下一单位资本的最有效用途，以及现有持仓和其他合法资本用途为何未胜出。风险许可禁止新增部署时，也不得跳过候选扫描、持仓复核或资本竞争；但不得因此授予Trial、Confirm或新增交易权限。上述判断属于MASTER既有统一资本比较的必要解释，不构成新增固定评分、排序、机会身份、交易许可或独立输出章节。旧仓卖出与新机会买入必须分别决议。

**双向对称资本竞争与反事实检验（适用于每次正式决策，不以新增部署是否为0元作为触发条件）：**

1. **持仓端逐只比较。** 每只实际持仓必须比较继续持有、部分减仓和全部退出，并与现金、其他持仓、合格机会及可合法释放资本比较。必须回答：如果当前没有该持仓，是否仍愿意按当前价格和证据重新配置资本；继续占资相对现金和替代用途的边际收益风险是否胜出；部分释放或退出分别解决什么问题。选择继续持有时，必须说明继续占资优于释放资本的具体理由，并覆盖迁移成本、失败风险、旧仓赢家右尾和账户功能。不得以“尚未破位”“没有卖出信号”“已经持有”代替比较。未能证明继续占资优势的对象必须进入释放评估；释放评估不等于卖出授权，实际卖出仍独立遵守MASTER卖出链。

2. **机会端逐只比较。** 对本次已经形成且通过身份、时点、质量核验的机会评估对象，必须明确判断Trial、直接Confirm和0元三个方案。Trial评估必须说明是否达到5,000元Trial标准及相对0元的事前收益风险优势；直接Confirm评估必须说明是否已经独立达到Confirm证据标准、为何不需要先Trial，以及相对Trial和0元的边际优势；选择0元时必须说明Trial和Confirm各自未成立的决定性原因，以及现金或其他资本用途为何胜出。不得因风险偏好保守、Trial存在失败概率、已有持仓或现金充足而自动拒绝已合格机会。Discovery和观察ETF必须先通过MASTER规定的机会资格判断，不得因参加比较而升级身份或获得交易权限。

3. **未达机会资格的候选。** 对仍处于Discovery、观察或观察机会状态、尚未达到Trial/Confirm资格的对象，明确说明其当前不具备哪一项决定性条件、可观察的补齐或证伪事实及最近复核节点；不得强行把所有扫描对象纳入可交易机会，也不得用“继续观察”代替可证伪条件。

4. **统一反事实与胜出用途。** 持仓端与机会端采用相同资本基准，比较事前预期收益、失败损失、右尾贡献、边际风险收益、证据质量、重复暴露、资金占用、机会成本、迁移成本和执行可行性。必须明确当前胜出用途及未选择方案的反事实理由。无法判断胜出者时披露具体信息缺口和最近复核节点，不得默认持有、默认保留现金或强行交易。

   **重复暴露的语义边界：** 共享纳指/美股/汇率/宽基或大类行业因子，只能作为组合共同风险输入，不能直接等同于同一交易逻辑或独立机会否决。必须区分“共享风险因子”与“相同收益驱动、相同交易假设及相同失效条件”；不同细分行业、产业链位置或可证伪价格/承接假设，即使共享宽基因子，也必须先独立判断其机会资格，再把共同风险计入组合与金额比较。只有真正表达同一交易逻辑的高度同质工具，才应竞争一个主要风险表达。若以共同暴露为由选择0元，必须进一步说明共同风险如何改变本次组合的边际风险收益、为什么新增或替换均不胜出；仅写“与现有持仓重复/相关性高”不构成完整理由。

   **三路径资本反事实：** 对已经达到机会资格、且与现有持仓存在共同因子的候选，必须在同一资本基准下比较：①保留旧仓并新增候选；②对边际效率较低的旧仓独立评估减持/退出，再以合法释放资本配置候选；③维持当前持仓与现金。逐路径解释共同风险、候选独立收益驱动、组合边际风险、迁移成本、赢家右尾和执行约束。旧仓没有卖出决议或尚未实际释放，不得自动阻断候选自身Trial/Confirm判断；也不得为了买入候选而倒推旧仓卖出。旧仓卖出与新机会买入仍须分别通过各自完整链条。

   **Observation身份与节点机会分离：** Discovery候选未ADMIT为持续观察ETF，或因持续信息价值不足而REJECT Observation，不等于否定其本节点机会角色。该候选仍须在本节点独立回答机会状态、Trial、直接Confirm和0元；若尚未达到机会资格，明确缺失的决定性证据。不得把Observation准入作为Discovery机会参与资本比较的前置许可。

5. **独立决议和交易边界。** 旧仓减仓/退出与新机会Trial/Confirm分别决议；旧仓未释放不自动否决合格机会，机会成立也不自动触发旧仓卖出。上述比较不新增评分、机械排名、交易状态、金额档、风险许可、卖出标准或交易权限。所有交易仍由用户确认并人工执行。

上述要求属于MASTER既有统一资本比较的逐对象解释合同，不新增独立输出章节、机会身份或交易节点；应在既有【全市场机会与资本竞争】、【机会ETF逐只评估】及【全部实际持仓】中自然呈现。

证券首次出现使用“名称（六位代码）”格式，同一对象全文保持一致。

用户正文不得出现请求编号、路径、提交信息、内部状态、workflow、job、完成记录、报告、通知中心、服务商、代码字段或内部日志。

冻结前必须完成事实边界、时点、对象覆盖、建议与执行区分、结构排版和内部字段泄露检查。冻结后不得摘要、缩短、改写、拼接、重新编号或重新分析。

## 六、唯一生产交接链

FINAL_CONTENT冻结后，必须直接进入 current main 登记的统一 Scheduled Review direct completion writer，并继续沿同一运行身份、同一事实快照和同一冻结正文交接。统一 direct completion writer 是唯一生产入口；不再设置 Formal Decision Actor 或其他适配器作为生产入口：

唯一运行身份
→ current main最近合法固定时段事实
→ 新鲜度判断
→ 合法准入
→ 唯一 FINAL_CONTENT
→ current main 统一完成记录生产者
→ 正式事件
→ 正式报告
→ 通知记录
→ 服务商投递结果
→ 用户收到状态。

这里的“调用”必须是实际提交并回读统一 direct completion writer，不得只在用户回复中声明已调用。正文发布后，若运行环境暂时不能提交或回读后置交接，只能如实记录最后完成层级和用户收到状态，不得因此阻断已经冻结的正式正文。

direct completion writer 不得创建第二请求、第二正文、第二完成记录、第二事件、第二报告或第二通知链；不得直接手写事件、报告、通知或调用服务商。

完成记录必须由统一生产者生成并回读；生产入口接收并校验本次唯一 Formal Decision completion，且该记录必须属于当前运行身份。至少核对：

- task_id、task_run_id、occurrence_id、request_id；
- source、entry_mode、market_date；
- interaction_scenario、report_type=ETF_FORMAL_DECISION；
- 统一完成记录的请求类型固定为 `SCHEDULED_REVIEW_COMPLETION`；
- 完整 FINAL_CONTENT 和 content_hash。

完成记录形成不等于事件、报告、通知或用户收到形成。

## 七、事件、报告与通知回读

完成记录成功写入并回读后，必须沿 current main 既有正式决策生产路径继续处理。

每层必须绑定本次运行身份、occurrence_id、decision_id、正文和正文指纹，并分别回读。正式事件按本次 occurrence_id 写入 `events/reviews/formal_<occurrence_id>.json`，再回读：

- 完成记录；
- 正式事件；
- 正式报告；
- 通知记录和通知编号；
- 服务商投递结果；
- 用户收到状态。

每次轮询约15秒，单层最长6分钟。不得扫描历史对象、使用旧正文或旧通知补齐本次运行。

必须严格区分：

- 完成记录形成；
- 正式事件形成；
- 正式报告形成；
- 通知记录形成；
- 服务商投递成功；
- 用户实际收到。

workflow成功不等于上述任何后续状态成功；服务商成功不等于用户实际收到。

## 八、失败、恢复和最终回复

任一层失败，必须沿同一运行身份、同一冻结 FINAL_CONTENT 和同一已形成的完成记录继续恢复，不得重新分析或创建第二链。

如果事实未达到合法准入且达到合法终止条件，只能说明本次未形成正式判断，并说明最后完成层级和事实阻断。

如果 FINAL_CONTENT 已冻结，即使后置交接失败，也必须输出同一份完整正文，并在正文后说明：

- 已完成层级；
- 未完成层级；
- 失败原因是否确认；
- 是否需要沿同一运行身份继续恢复；
- 用户收到状态。

不得把技术失败改写成业务结论，不得把完成记录、事件、报告、服务商成功或用户收到混写为同一状态。

## 九、历史兼容对象

历史 BDS、旧完成记录、旧事件、旧报告和旧通知可以保留为审计档案，但不得作为当前 Formal Decision 的事实、准入依据、正文来源或生产输入。

Formal Decision 的 workflow、测试和治理检查不得创建、读取或依赖 BDS。若共享状态同步模块暂时保留历史兼容读取，其作用域必须限于非 Formal Decision 的历史状态同步，不得被 Formal Decision 请求、完成记录、事件或通知链调用。历史档案不属于当前生产链。

本协议不新增生产链；它只约束统一完成记录生产者、正式事件、报告和通知链。
