# ETF定时任务验收基线｜2026-10-12

## 目的

本记录封存2026-10-12三个ETF定时任务修复后的验收基线、已验证经验和后续变更门槛。它是审计与验收记录，不构成第二任务、第二workflow、第二state、第二producer、第二writer或第二通知链。

## 当前基线

三个任务均保持现有任务身份、启用状态、时区、调度、完成入口和通知链不变：

- 【ETF系统复核】：交易日08:30、19:30；周日19:30周复核。
- 【ETF交易复盘】：交易日12:30、20:30；周日20:30周复盘。
- 【ETF正式决策】：交易日10:00、11:00、13:30、14:30。
- 不适用节点继续由任务自身按current main正式日历、市场阶段和既有合同SKIP，不通过修改调度实现。

## 已验证成功

1. 正式决策已恢复唯一FINAL_CONTENT、首行标题、报告优先输出、既有完成入口提交和主动通知闭环。
2. 系统复核和交易复盘已能生成完整报告并收到主动通知。
3. 二级编号已统一要求使用1）、2）、3），逐项独立成段，项目之间使用两个真实换行。
4. 协议已固化分层归因：Prompt、执行器时序、GitHub完成入口、通知适配器、PushPlus/微信渲染层和业务规则层必须分别诊断。
5. Prompt版本保护已固化：更新前保存完整旧Prompt、任务身份、时间戳/版本、哈希、变更原因和回滚位置；失败时优先回滚最近已验证版本。

## 今日失败经验

1. 曾将首行、二级编号、通知和报告内容同时作为Prompt问题处理，导致修复范围扩大并出现格式回归。
2. 曾以“首行显示已修正”判断通知链也已修正，实际存在报告、完成记录、通知发送和用户收到四个不同状态。
3. 曾在通知未成功时继续调整正文格式，未先区分通知适配器/投递链和Prompt层。
4. 结论：同一用户症状不等于同一技术层；一次只修一个明确层和一个明确行为，必须沿真实目标路径验证。

## 后续变更门槛

再次修改任何定时任务Prompt前，必须完成：

1. 读取current main和当前云端Prompt。
2. 保存旧Prompt完整快照及哈希、任务身份、时间戳、变更原因和回滚位置。
3. 明确故障所属层级，以及本次只改变的一个行为。
4. 说明不改变的合同：调度、业务规则、provider、权限、完成链、通知链和其他任务。
5. 先在隔离分支验证，再通过PR进入main；不得直接覆盖main或依赖聊天历史恢复旧指令。
6. 若出现通知缺失、首行/编号回归、业务边界漂移或任务身份变化，优先回滚，不追加补丁。
7. 未取得新的可复现故障前，禁止继续优化格式或重写Prompt。

## 验收状态定义

报告生成、完成记录、通知发送、用户收到必须分别记录。报告完成不等于完成记录成功；通知发送不等于用户收到；格式正确不等于业务闭环完成。未取得对应证据时，只能表述为未确认，不得宣布完整闭环。

## 结论

当前进入基线冻结状态：不再追加Prompt内容，不调整调度，不创建旁路链。后续生产动作只由新的可复现故障触发，并遵守上述单层、单行为、可回滚变更门槛。
